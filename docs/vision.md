# Vision

**Transform my GitHub from a collection of learning repositories into a professional engineering portfolio that showcases my skills, growth, and open-source contributions while improving my chances of securing software engineering interviews.**
## Goals

- Professional appearance
- Consistent documentation
- High-quality READMEs
- Clear project organization
- Strong recruiter impression
- Sustainable workflow for maintaining GitHub quality

## Principles

1. **Plan before editing** — classify and prioritize repositories before making changes.
2. **Review everything** — AI drafts; humans approve permanent changes.
3. **Track progress** — use issues, epics, and milestones like a real engineering team.
4. **Automate repetition** — inventory, scoring, and reporting should be scriptable.
5. **Preserve history** — archive or privatize rather than delete when uncertain.
6. **Finish before expanding** — complete the current sprint before planning the next one.

## Success Criteria

- Every public repository has a clear purpose, description, and README.
- Portfolio repositories are polished and pinned on the profile.
- Forks, tutorials, and experiments are classified and handled appropriately.
- A repeatable workflow exists for ongoing GitHub maintenance.
